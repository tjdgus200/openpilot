# PV5 모델 우선 HUD 전송 — 2026-11-07

## 변경 이유와 동작

기존 USB owner는 모델 요청 뒤 `infer_end`로 응답을 받기 전에 HUD 스냅샷과
지도 조각을 동기 전송했다. GPU가 결과를 준비했어도 이 쓰기가 늦으면 콤마로의
결과 전달도 늦어질 수 있었다. 추론 ms 표시 자체는 기존 모델 메시지의 읽기다.

이제 모델 요청 → 필수 모델용 map staging → 모델 결과 수신·검사 → 콤마 IPC
응답 순서를 먼저 끝낸다. HUD/지도는 이 구간에서 전송하지 않는다.

응답 뒤와 IPC 대기 중에만 아래 조건을 모두 만족하면 표시를 보낸다.

- 읽지 않은 모델 요청이 없다. 부분 헤더 하나도 모델 요청으로 우선한다.
- 다음 모델 요청의 예상 시점까지 최근 표시 비용과 4ms 여유가 남아 있다.
- 각 표시 처리의 2ms 허용 구간이 아직 끝나지 않았다.
- 느린 모델 교환(45ms 이상) 또는 표시 처리(2ms 초과) 뒤 한 모델 주기(최대 50ms)의 재시도 대기 상태가 아니다. 처음 적용했던 2초 대기는 HUD 데이터 만료와 맞지 않아 연결 안정화 수정에서 줄였다.

스냅샷 읽기 뒤에도 모델 요청과 시간을 다시 확인한다. 읽기 중 모델 요청이
도착하면 그 스냅샷은 버린다. 지도는 각 조각을 꺼내기 전에 다시 확인하고,
미전송 조각의 순서를 유지한다. 밀린 스냅샷을 큐에 쌓거나 몰아서 보내지 않는다.
표시 비용에는 스냅샷 읽기와 지도 전송도 포함한다. 모든 FPS 선택에 적용한다.

## 보존한 계약과 한계

모델 텐서·입력 크기·FOV·출력·반복 상태·reset·출력 finite 검사·필수 모델 지도
staging·부분 IPC 수신 기한·USB watchdog·차량 제어는 변경하지 않는다.
기존 모델별 Jetson 아카이브/핀과 렌더러는 유지한다. 이 수정의 동작 주체는
콤마의 USB owner이며 Jetson 설치나 새로운 패키지를 요구하지 않는다.

2ms는 **다음 전송을 시작할지 판단하는 허용 구간**이며 진행 중인 USB 쓰기를
2ms 안에 강제 종료한다는 뜻이 아니다. 공유 FunctionFS 스트림에서 일부 전송한
메시지를 취소하거나 타임아웃을 무시하면 모델 프레이밍까지 손상될 수 있어
기존 실패·복구 처리를 유지한다. 쓰기 시작 직후 새 모델 요청이 생기거나 실제
USB가 멈추면 다음 요청이 늦어질 가능성은 남는다. 물리적인 무간섭은 보장하지
않으며 별도 통신 경로/프로토콜 설계 없이 그런 보장을 주장하지 않는다.

Q92와 저장 FPS는 유지하되 추론이 바쁘면 HUD 실제 갱신률이 낮아질 수 있다.
전체 진단 수집은 기본 OFF, 기존 1Hz 자원/추론 시간 표시는 유지한다.

## PC 검증

필수 `pv5_model_checklist.json`에 모델 우선 전송·실제 daemon 순서·지도 순서
회귀 검사를 추가했다. 모델별 기존 FOV/출력/중앙 보정/HUD 보존 검사도 실행한다.
최종 코드의 필수 PC 검사는 **1,001 passed, 0 failed, 0 skipped**다.

- 합성 모델 응답 8/80ms, USB HUD 유무, navigation/pump 유무, 출력 projection,
  지도 staging 조합에서 동일 모델 입력·출력·frame ID·timing 계약을 검사한다.
- 3/20/100ms 표시 정체를 모사해 추가 지도 전송과 후속 표시를 중단한다.
- 스냅샷 읽기 중 모델 요청 도착, 부분 IPC 헤더, 조각 사이 요청 도착, 전송 순서,
  느린 스냅샷 읽기와 실제 USB 쓰기 실패의 기존 연결 종료 처리를 검사한다.

이는 PC fixture의 실행 순서·동등성 검사이며 실제 Orin/USB 지연·주행 검증이나
성능 향상 수치가 아니다. 최종 검사 JSON은 워크스페이스의
`jetson-nvme/pv5-hud-idle-priority-20261107/`에 보관한다.
