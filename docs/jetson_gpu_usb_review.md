# Jetson GPU state / USB completion review

기준: 공식 `carrot-nav`의 `3a03a39f2d1277d8d85c16c100ebb05f75052f79`
(2026-10-21 확인). 사용 중인 `carrot-nav-pv5`와 별도의 검토용 브랜치다.
제작자가 기능별로 검토할 수 있도록 변경을 별도 커밋으로 나눈다.
기존 개인 HUD·배터리·Wi-Fi 정책, 비동기 USB 송신, 모델 교체와 배포 파일은 포함하지 않는다.
이 브랜치의 커밋으로 공식 PR을 자동 생성하거나 기기에 설치하지 않는다.

## 1. GPU 상태 유지 — 기본 OFF

공식 코드도 이전 추론 상태를 다음 입력으로 전달한다. 다만 출력 상태를 pinned
CPU 메모리로 내린 뒤 다음 추론에서 다시 GPU로 올린다. 이 제안은
`CARROT_TRT_DEVICE_STATE=1`일 때만 상태 H2D/D2H를 생략하고 GPU에서 다음 입력
버퍼로 D2D 복사한다. 기존 서로 다른 GPU 입력/출력 버퍼와 호스트 버퍼 수명은 유지한다.

현재 카메라·스칼라/지도 입력은 매번 새로 올리고 주행 출력은 CPU로 돌려준다.
모델 가중치 상주와는 별개이며, 과거 주행 결과 재사용이나 프레임 생략이 아니다.
전달 형식·모델/출력 계약·주행 제어 조건·IPC 마감을 변경하지 않는다.

- GPU에서 모든 상태 출력의 float16/float32 유한값을 검사하고 상태 워드 4바이트를
  CPU로 복사한다. 주행 출력의 기존 CPU 검사도 유지한다.
- 같은 CUDA 스트림에 검사 → 응답 이벤트 → 다음 입력용 상태 복사를 순서대로 넣는다.
  CPU는 응답 이벤트를 기다리며, 뒤의 상태 복사는 다음 추론보다 먼저 실행된다.
- reset은 같은 스트림에서 다음 실행 전에 0을 채운다. 종료는 남은 스트림 작업을
  동기화한 뒤 이벤트·GPU/호스트 메모리를 해제한다.
- 지원하지 않는 상태 계약/형식, NVRTC 컴파일 또는 CUDA 오류가 있으면 요청 모드를
  거부한다. 검사 생략이나 이전 출력 재사용으로 성공처럼 표시하지 않는다.
- 환경값을 주지 않으면 기존 CPU 상태 경로다. 배포 옵션이나 서비스 환경을
  변경하지 않으므로 **병합만으로 자동 활성화되지 않는다.**

실제 사용하려면 제작자가 대응 Jetson 런타임을 빌드·검증·배포하고 활성화 환경값을
선택해야 한다. 콤마의 브랜치 교체만으로 기존 Jetson 런타임이 바뀐다는 뜻이 아니다.
공식 서명/NAS·USB 업데이트 형식이나 키를 바꾸는 패치는 포함하지 않는다.

### 검증과 성능 근거

최신 공식 기반의 이 검토본에서 PC 112개 통과, 선택적 실제 CUDA 1개는 별도 환경이
필요해 생략했다. 실제 TensorRT/Orin 실행이 아니라 순서가 지연되는 CUDA 대체 구현의
상태/주행 결과 비교·리셋·NaN/Inf 거부·복사/이벤트 순서와 기존 프로토콜/출력 검사다.
사용자의 이전 검토본 요청에 따라 추가 자동 테스트 파일은 커밋에 포함하지 않았으며,
로컬 검증 소스와 결과는 공개 소스 변경과 구분했다.

과거 C3/RL Nav 한 차례 시험은 GPU 상태 유지와 비동기 USB 송신을 **함께** 켰다.
Jetson 처리 평균 27.33→25.53ms, 전체 처리 평균 43.46→41.90ms,
P99 51.99→49.25ms, 최대 60.20→63.26ms를 관측했다.
이는 GPU 상태 유지 단독의 성능 효과나 현재 N16 성능 근거가 아니다.
[기존 시험 기록](https://github.com/tjdgus200/openpilot/blob/ef79ea37/docs/jetson_runtime_port_20261015.md)을 참고한다.
이 검토본에는 비동기 송신을 넣지 않았다. 실제 Orin에서 동일 엔진·입력으로 GPU
상태 OFF/ON을 각각 비교하고 비정상 값·재접속·장시간 실행까지 검증해야 한다.
주행 안전성이나 매 프레임 50ms 완료를 보장하지 않는다.
