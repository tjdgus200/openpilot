# PV5 모델 FOV 측광과 카메라 영역 확인

2026-11-08 사용자 요청. 기본 측광은 유지하며, `Pv5ModelFovExposure=1`일 때만
새 측광을 사용한다. `Pv5CameraFovPreview`는 이와 독립적인 표시 옵션이다.

## 메뉴와 표시

- PV5 → 주행 보조: 기존 차로 중앙 보정.
- PV5 → 카메라·노출 → 모델 입력·노출: 기존 광각 FOV, 새 FOV 측광.
- PV5 → 카메라·노출 → 영역 확인: 주행 중 2초 카메라 교대, 기존 pitch 비교선.
- 정차 자동 미리보기는 유지한다. 표시 옵션 ON이면 기어·속도와 관계없이 교대한다.
  기존 차량·보정 유효성, 경고 렌더 순서와 화면 스트림 변경 취소는 유지한다.
- 청록색은 모델 입력, 보라색은 측광 영역이다. 새 측광의 실제 영역과 black/white
  통계는 camerad의 같은 카메라 메시지에서 읽고 표시를 최대 2Hz로 갱신한다.
  메시지가 오래되거나 렌즈가 바뀌면 이전 영역을 지운다. pitch 후보는 항상 표시 전용이다.

## 구현 범위

`ModelFovMeter`는 모델 좌표의 균등한 64×36 표본을 원본 Y 버퍼에 대응시킨다.
이미지 복사·새 워핑·추가 추론·Jetson 왕복·modeld 응답 대기는 없다. 실제 Y 버퍼의
stride를 사용하여 행 패딩을 영상으로 읽지 않는다.
캘리브레이션과 FOV가 바뀔 때만 주소를 계산하고, 프레임마다 2,304개 이하의
픽셀에서 기존과 같은 상위 중앙값 히스토그램을 계산한다. FOV 밖 픽셀은 이 중앙값에
영향을 주지 않는다. dark<=5/255, bright>=250/255 비율은 표시 통계이며 새 제어 게이트가 아니다.

현재 구현은 KIA_PV5, C3/C3X, AR0231/OX03C10, 1928×1208, 일반각+광각이
모두 활성인 구성으로 제한한다. 두 카메라 각각 `model.py`의 입력 투영을 사용한다.
광각은 기본/65/70/75/80을 반영한다. 카메라 방향 보정과 카메라 시작 시 yaw trim을
사용하며, UI의 preview pitch를 사용하지 않는다. 모델 가중치·텐서 형상·모델 워프,
조향·종방향 제어·게인 점수·센서 레지스터/노출 한계는 변경하지 않는다.
센서에 들어가는 실제 밝기는 달라지므로 기존과 같은 추론 결과를 보장하지 않는다.

설정·차량 정보 읽기와 보정 메시지 처리는 SCHED_OTHER/nice10 전용 스레드에서 한다.
프레임 처리 스레드는 잠금 없는 원자 필드의 최신 스냅샷을 한 번만 읽으며,
동시 갱신 중이면 이전 값의 유효기간만큼만 유지한다. 재시도 루프나 대기는 없다.
최신값 SubMaster를 새 측광이 켜졌을 때만 사용하며 update(0)으로 기다리지 않는다.
설정 확인 주기는 250ms, 현재 CarParams는 최대 1Hz다. 실제 반영에는 스케줄링과
정보 수신 지연이 있을 수 있다. 최초 차량·보정 데이터
수신 전에는 기본 측광이다. 보정 메시지는 생성 후 1초, deviceState는 2.5초를 넘으면
기본 복귀한다. 보정 불완전/잘못된 값, 미지원 구성, 수동 노출 디버그,
모델 격자 표본의 90% 미만만 센서 안에 있는 경우, 0인 중앙값도 기본 복귀한다.
운전자 카메라는 항상 기존 측광을 사용한다. 옵션 OFF 시 기존 함수가 그대로 호출된다.
modeld의 yaw 설정 확인은 100회 루프마다라서 카메라와 동시에 바뀐다고 가정하지 않는다.
yaw trim 저장값 변경을 관측하면 기본 측광으로 돌아가며 저장값을 되돌려도 유지한다. 이 설정 변경 후에는
카메라와 모델 프로세스를 함께 재시작해야 새 측광을 다시 사용할 수 있다.

## 반복 전환 억제 (2026-11-08 후속 요청)

측광 방식 변경 때 노출 제어 상태를 초기화하지 않더라도 두 영역의 밝기가 다르면
입력 밝기가 출렁일 수 있다. 새 측광의 카메라별 진입 상태에 다음 규칙을 추가했다.

- 최초 ON과 오류 후 재진입 모두 유효한 프레임 측광이 **2초 연속** 확인된 뒤 허용한다.
  프레임 수 대신 단조 시계를 사용하며, 대기 중 관측 간격이 250ms를 넘으면 대기를 다시 시작한다.
- 원래 보정 1초/장치 2.5초의 유효기간은 늘리지 않는다. 새 패킷이 없는 짧은 간격에는
  아직 유효한 마지막 정보를 재사용한다. 무효 패킷이나 버퍼·좌표·중앙 밝기 이상은
  유예 없이 기존 측광을 선택하며, 프레임 선택 시점에도 정보 만료를 다시 확인한다.
- 실제 FOV→기존 측광 전환이 **최근 30초 안에 3회** 발생하면 해당 카메라의 새 측광을
  잠근다. 시간 경과나 정상 데이터 복구만으로 다시 켜지 않으며 잠금 중 격자 측광도 생략한다.
  OFF 설정을 수신한 다음 다시 ON하거나 camerad 재시작으로 재시도할 수 있다.
  웹에서는 끄고 1초 뒤 다시 켜는 절차를 안내한다. yaw 변경 잠금은 기존대로 재부팅이 필요하다.
- 보정/FOV 세대 변경은 정상 갱신이며 실패 횟수나 잠금을 초기화하지 않는다.
  대기 중 실패나 계속되는 무효 프레임은 실제 FOV→기존 전환이 아니므로 횟수에 더하지 않는다.
- 기존 노출·게인 조정 함수, 목표 밝기 필터, 센서 지연 보상·한계 및 운전자 카메라는 유지한다.
  새 타이머는 측광 방식의 재진입만 제어하며 프레임 처리에서 기다리지 않는다.

2초/30초/3회는 반복 전환을 제한하기 위한 구현값이다. 실차 최적값으로 검증한 값이 아니며,
물리 카메라의 과도 응답·터널·야간에서의 효과와 부작용은 별도 확인해야 한다.

## 검증 및 한계

- C++ 샘플러를 실제로 컴파일해 Python의 모델 워프와 광각 선택/보정 조합을 비교한다.
- 격자 밝기 중앙값/포화 비율, 입력 밖 밝기 변화에 대한 독립성, 짧은 버퍼·잘못된 좌표·잘림을 검사한다.
- 실제 camerad 번역 단위를 현재 스키마/저장소 헤더로 컴파일 검사한다.
- 네이티브 타임라인으로 정확한 2초 경계, 다양한 관측 주기, 30초 이동 구간, 반복 실패 잠금,
  옵션 재시도·시계 역행·정상 장기 지속을 확인한다. 실제 프레임 선택 코드를 사용한 fixture에서
  버퍼·만료·센서·좌표·검은 영상 오류 7종과 보정 세대 갱신, 실제 측광 상태 게시를 검사한다.
- 주행 중 ON/OFF, 2초 교대, 정차 복귀, stale/invalid 입력, 실제 측광 영역 표시를 검사한다.
- 영구 PV5 PC 체크리스트와 웹 설정·문서 생성 검사를 실행한다.

픽셀 표본 수 감소는 연산량 모델이며 C3X CPU 절감 실측이 아니다. PC 녹화 재생으로
노출을 바꿔 촬영했을 때의 인식 정확도, 실제 노출 응답/빛 번짐/USB 지연을 증명할 수 없다.
기존 대비 야간/터널/역광/헤드라이트에서 물리 카메라와 모델 동작 비교가 별도로 필요하다.
새 기능은 기본 OFF이며 장치의 저장 설정을 임의로 켜지 않는다.
