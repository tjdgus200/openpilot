# Jetson HUD 데이터 공백 중 화면 유지 — 2026-11-07

## 재현한 코드 경로

`hud.py`의 `QualityWatch.read()`는 500ms 이상 신선한 HUD 스냅샷이 없으면
인코더 설정이 바뀐 것처럼 반환했다. 공통 main loop가 이를 받고 화면을 닫으면
USB close가 밝기를 0으로 만들고 panel owner가 해제되어 boot display로 넘어갔다.
다음 스냅샷에서 화면을 다시 열기 때문에 모델이 정상이어도 정상 화면·검은 화면·
연결 준비 화면이 반복될 수 있었다.

직전 모델 우선 수정의 느린 I/O 뒤 2초 표시 중단은 수신 데이터의 500ms TTL보다
길어 이 경로를 더 자주 유발할 수 있었다. PC 가상 시간으로 20Hz 모델과
3/6/8ms 표시 쓰기를 60초 실행해 이 불일치를 검사한다. 이번 차량 증상의
정확한 원인이 이 경로 하나뿐인지는 장치 기록 없이 단정하지 않는다.

## 수정

- 스냅샷 공백은 차량 정보의 유효성 상태로 처리한다. 이미 열린 renderer와
  USB panel owner는 유지하고 기존 연결 대기 strip과 `--`를 같은 화면에 그린다.
- freshness·BSD·차선·경고 만료를 늘리거나 오래된 차량 값을 정상으로 표시하지 않는다.
- 최초 한 번은 유효한 차량 데이터가 올 때까지 boot diagnostics가 화면을 유지한다.
- FPS 설정 변경, 실제 시동 OFF, 실제 USB/인코더 오류, 업데이트 종료는 기존대로 처리한다.
- 느린 전송 뒤 재시도 대기는 한 모델 주기, 최대 50ms로 줄인다. 모든 모델 요청
  우선순위·4ms 예약 여유·2ms admission window·부분 IPC/USB 프레이밍 계약은 유지한다.
  여유가 없으면 화면 전송을 계속 생략하며 모델 앞에 표시 쓰기를 넣지 않는다.

## 검증과 배포

필수 PC 목록에 실제 HUD main loop/FPS watcher, hotplug와 장시간 표시 admission
검사를 포함한다. 0.1/0.6/2.1/10초 데이터 공백에서도 화면 소유권을 한 번만
획득하고, 신선한 설정 변경에서는 다시 열며, 명시적 시동 OFF는 전달하는지 검사한다.
RemoteSubMaster는 공백 중 기존 alive/valid를 반드시 지우는지 별도로 확인한다.

다섯 모델 각각의 실제 아카이브에서 독립 import, packaged watcher, native HUD의
0.6/2.1/10초 공백과 복구 프레임을 렌더링하고 창·폰트를 유지하며 `--`/연결 대기
strip을 표시하는지 확인한다. 기존 모델/FOV/보정/팝업/자원/전원 동작도 유지한다.
원본 ONNX와 모델 사양은 바꾸지 않는다.

이 수정은 **Jetson HUD 코드도 변경**한다. 콤마의 모델별 USB 패키지 핀까지
갱신하며, 기존 정차/P단/오프로드 업데이트 자격과 설치 실패 시 이전 버전 보존을
유지한다. 단순 콤마 코드 변경만으로 이미 실행 중인 예전 Jetson HUD가 바뀌지는 않는다.
PC 검사는 실제 Orin/USB 장치·온도·주행 안전 검증을 대신하지 않는다.
