# PV5 여러 지점 곡률 중앙 보정

기존 `Pv5LaneCenterAssist` 옵션을 유지하고, 보정 계산과 차선 품질 가중만
갱신한다. PV5 전용·기본 OFF이며 저장한 선택을 강제로 바꾸지 않는다.
이번 승인 범위에는 한쪽 차선만으로 보정하거나 앞차·BSD 차단을 푸는 변경이 없다.

## 원본과 적용 범위

- 원본: [sunnypilot Blendful #2073](https://github.com/sunnypilot/sunnypilot/pull/2073),
  `97135965effb3630ed55993903449edb73468d50`.
- 확인한 ZoomPilot 개발 브랜치:
  [`92e1ecbd0459`](https://github.com/zoompilot/zoompilot/blob/92e1ecbd0459ce8d3685b29bb2937b7283478af3/openpilot/sunnypilot/modeld_v2/blendful.py).
- 다지점 최소제곱 곡률 잔차와 모델 action/plan 혼합, 확률·표준편차 가중을
  현재 발행되는 `modelV2` 필드에 맞게 적용한다. 완전한 Blendful 복제는 아니다.
  원시 모델 출력의 지점별 표준편차 대신 기존 메시지의 차선별 스칼라를 사용한다.
- 차로 폭 학습·한쪽 차선 추정·회피 이력 판단은 가져오지 않는다.
  원본의 18km/h 최저 속도 제한도 복원하지 않는다.

## 계산과 유지 조건

1. 새 모델 프레임에만 최대 33개씩의 좌·우·모델 경로 좌표를 검사한다.
   좌표 유한성·단조 증가·동일 길이를 확인하고 외삽하지 않는다.
2. 기준 거리 `max(max(v,5)*1.5,10)`m의 0.5~1.5배 구간을 9지점으로 검사한다.
   공통 경로가 짧으면 끝을 자르되 최소 기준 거리까지는 자료가 있어야 한다.
3. 차로 폭 2.8~4m, 전방 폭 변화 0.2m 이내, 모델 경로와 중앙의 차이
   0.3m 이내·그 변화 0.12m 이내 조건을 확인한다.
4. 차선 중앙에서 모델 action의 포물선과 모델 경로를 혼합한 값을 뺀 잔차를
   `delta_curvature*x²/2`에 맞춘다. 커브가 커지면 plan 비중은 30~50%이다.
   원본 방식의 계산 결과를 PV5의 추가 횡가속도 0.08m/s²로 제한한다.
5. 양쪽 차선 확률은 각각 50% 이상·표준편차는 0.6m 미만이어야 한다.
   `확률 * clip((0.6-std)/0.4,0,1)` 중 낮은 품질로 강도를 줄인다.
   품질은 즉시 낮추고 상승은 0.5초 필터를 거친다. 지연·누락을 필터로 숨기지 않는다.
6. 기존 0.5초 연속 확인·0.5초 진입 ramp, 반대 방향 재확인,
   250ms 설정 확인과 모든 운전자·BSD·선행차·기동·신선도·레인모드 차단을 유지한다.
   새 프레임 간 시간이 0 이하 또는 0.2초 초과이면 이력과 보정을 지운다.

기존 `abs(action_curvature)*v² <=0.6` 및 전방 차로 중앙의 절대 위치
0.75m 조건은 커브에서 정상 기하도 차단했다. 이 두 조건을 위 곡선 기하
검사로 대체한다. 추가 보정 상한과 저속 곡률 분모 하한, 이후 기존 smoothing,
angle/rate/physics/CAN 한계는 바꾸지 않는다. 기존 0.25배 위치오차 식은
위 곡률 피팅으로 대체되므로 ON 출력이 기존과 같지는 않다.

## PC 검증과 결과

비교 기준은 `540dbfb30239e9e399e3c4dfa3772dbb24834701`이다.
실제 `Controls.state_control`, `LatControlAngle`, 현대·기아 각도 제한과 CAN
패킹을 실행했다. 모델의 인식·정책, 차량 운동 및 EPS는 실측 보정하지 않은 가정이다.
실제 카메라·신경망·레이더 재생 또는 실차 주행 시험이 아니다.

- 8초 비교 96조건: 54/90km/h, 좌/우, 횡가속도 0/0.8/1.8m/s²,
  모델 목표 중심 편향 ±10cm, 확률 99%/84~86% 반복, 응답 지연 0/120ms.
  시작 횡오차는 ±15cm이고 차선 기하가 정확하다고 가정했다.
- 추가 16조건: 모델 목표는 중앙이고 시작 오차는 0이지만, 신뢰도 99%인
  양쪽 차선이 함께 ±15cm 틀렸다고 가정했다. 54/90km/h,
  횡가속도 0.8/1.8m/s²와 지연 0/120ms를 조합했다.
- 두 방식 모두 112조건·179,200 제어 tick에서 보정·각도 한계,
  25~250 보조력 범위, 실제 CAN 패킹과 출력 유한성 검사를 통과했다.

| 조건별 결과의 중앙값 | 기존 | 변경 |
| --- | --- | --- |
| 정확한 차선 96조건: 평균 절대 횡오차 | 9.70cm | 7.77cm |
| 정확한 차선 96조건: 8초 후 절대 횡오차 | 10.00cm | 6.32cm |
| 잘못된 차선 16조건: 평균 절대 횡오차 | 0.038cm | 2.95cm |
| 잘못된 차선 16조건: 8초 후 절대 횡오차 | 0.001cm | 3.96cm |

정확한 차선 조건의 평균 오차는 96개 모두 줄었고, 조건별 감소율 중앙값은
22.89%다. 초기 15cm가 지배하는 최대 오차는 모두 같아 최대 이탈 개선을
주장할 수 없다. 잘못된 차선 조건은 16개 모두 악화했다. **차선 인식 확률은
위치의 정답 보증이 아니므로, 차선 보정이 모델보다 항상 맞는다고 가정하면 안 된다.**
이 결과는 실차 개선율·안전성 또는 차선 이탈 방지의 증거가 아니다.

PC 고정 입력, 각 경로 2,400~3,000회 측정에서 helper 평균 비용은 새 프레임
28.58→70.98µs, 기존 프레임 11.43→12.03µs였다. OFF/BSD 차단 경로는
측정 잡음 내에서 같았다. C3X·Orin 지연은 미측정이다.
추가 신경망·worker·Params polling·USB 필드·런타임 성능 계측은 없다.

기존 5모델의 FOV·파서·반복 상태·HUD·BLE·전원/업데이트 필수 검사를 실행한다.
새 기하·품질·시간 단절 검사를 영구 모델 체크리스트에 추가했다.
최종 필수 PC 검사는 **2,051 통과·실패 0·스킵 0**, 실제 control loop·시작 조건·
조향 복귀·각도 한계 별도 검사는 **282 통과**다. 두 그룹은 일부 겹치므로
고유 검사 수로 합산하지 않는다. 사용자 가이드 validator, Wiki 생성 테스트13개와
변경 Python 정적 검사도 통과했다. 원격 CI 결과와 실물 검사는 별도다.
초기 PC 시험의 Params 경계/스키마 참조 오류와 테스트 import 수집 오류는
시험 환경을 바로잡고 재검사했으며 통과로 덮어 기록하지 않는다.

## 실물 확인 범위

물리 EPS 반응, 실제 카메라/차선 오인, 운전자 개입감, C3X의 실시간성 및
모든 실제 모델 출력에 대한 주행 안전성은 미검증이다. 실차 검증 전 기본 OFF를 유지한다.
Jetson 추론/렌더러를 수정하지 않으므로 모델별 패키지를 재발행하지 않는다.
