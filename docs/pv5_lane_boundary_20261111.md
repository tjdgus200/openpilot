# PV5 차선 접근 보정 — 2026-11-11

사용자가 지속 중앙 보정 대신, 깜빡이가 없을 때 차선에 가까워지거나 침범하면
안쪽으로 보정하도록 변경을 요청했다. 이 결정은2026-11-10 원본 Blendful의
**런타임 사용**을 대체한다. 원본 소스와 골든 검사는 이력/비교용으로 보관한다.

## 적용 경로와 설정

- 캐럿웹 **설정 → PV5 → 주행 보조 → 차선 접근 보정 (실험)**.
- 새 키 `Pv5LaneBoundaryAssist`, 기본OFF. 이전 `Pv5LaneCenterAssist` 값은
  삭제하거나 승계하지 않고 런타임에서는 읽지 않는다. ON은 새 기능에 명시적으로 한다.
- `modeld`의 Blendful 호출/결과 추가를 제거한다. 모델 입력·출력·반복 상태·
  종방향 action은 그대로이며 내부 CD210과 다섯 Jetson 모델이 같은 제어 경로를 쓴다.
- controlsd에서 선택한 모델/Carrot 레인모드 원래 곡률에 **한 번만** 보정하고,
  기존 평활화·곡률 변화율·앵글 컨트롤러·차량 각도/속도/물리/CAN 제한을 통과한다.
  평활화 뒤에 반복 추가하면 이전 보정이 누적될 수 있어 그 방식은 쓰지 않는다.
- 실제 PV5만 helper를 생성한다. 기존 lateral admission/AlwaysLateral의
  허용을 따르며, 이 기능이 별도로 크루즈나 횡제어를 켜지 않는다.
- 기존 wire 필드의 이름과 tag는 호환성을 위해 유지하고 C3X/HUD 소스의
  표시를 `차선 보정`으로 바꾼다. 기존 배치·경고 우선순위·차선 인식/스티어는 유지한다.

## 개입 기준 — 실험값

기아 [PV5 Cargo 한국 공식 제원](https://www.kia.com/content/dam/kwp/kr/ko/vehicles/pdf/en_brochure/en_catalog_pv5-cargo.pdf)의
차체 폭1.895m를 사용한다. 미러·실제 타이어 위치·장착 오차를 직접 측정하는 값이 아니다.
차체 가장자리와 인식 차선 사이20cm를 시험 여유로 둔다. 속도0.8초에 해당하는
8~20m 앞, 다섯 점에서 선택 곡률의 예측 경로와 차선 사이 여유를 비교한다.

각 차선 경계로부터 허용되는 곡률 구간을 만들고, 선택 경로를 그 구간에
가장 적게 이동시킨다. 중앙을 목표로 피팅하지 않는다. 따라서 차로 안에서
중앙을 벗어나도 여유가 있으면 추가 보정은 정확히0이다. 이미 충분히 안쪽으로
복귀하는 경로에도 보태지 않는다. 추가 횡가속도는 최대0.30m/s²,
증가율0.50m/s³다. 새 목표가0이면 추가량을0으로 지우되 최종 조향 전환은
기존 평활/변화율 제한이 처리한다. 이 값들은 차량에서 검증한 안전 한계가 아니다.

조건:

- 별도18km/h 문턱 없음. D단, 정차/정확한0속도 아님, 기존 횡제어 활성, 정상 CAN.
  기존 차량의 최소 조향 허용 기준은 이 기능이 우회하지 않는다.
- carState/modelV2가 seen/valid/alive이며 수신 나이0~0.20초.
- 실제 해당 차선 확률≥0.75·표준편차≤0.35m·유한하고 순증가하는 좌표.
  반대쪽 차선을 추정하거나 차로 폭을 학습해 가상의 차선을 만들지 않는다.
- 양쪽이 보이면 차로 폭2.6~4.8m와 서로 모순되지 않는 곡률 구간을 확인한다.
  이미 차체가 선을35cm 넘었거나 좌표/기하가 모순되면 되잡으려 하지 않는다.
- 좌/우 어느 깜빡이든 켜짐과 해제 후1초, 모델 방향 전환/차선 변경,
  운전자 steeringPressed에서는 추가량을 즉시 지운다.
- 시간 역행/간격 이상·중복/역행 프레임·신선도/입력 이상도 보정을 지운다.
  선택한 경로가 바뀌면 캐시된 보정량을 그대로 더하지 않고 새 곡률에 투영한다.

차선 배열은 새 모델 프레임에서만 처리하고 제어 틱에서는 캐시된 경계에
스칼라 연산만 한다. 추가 추론·워커·상시 프로파일러·디스크 기록은 넣지 않는다.
설정은 기존250ms 주기로 읽는다.

## 검증과 한계

PC 단위/실제 제어 루프/다섯 모델 파서→메시지→controlsState→HUD 직렬화,
OFF/비대상/차로 안쪽의 원래 출력 동일성, 신호·운전자 즉시 양보,
좌우/곡선/품질/시간 고장과 원래 조향/CAN 한계를 검사한다.
최종 결과와 비용은 `workspace/pv5-lane-boundary-20261111`에 보관한다.

48조건 비교는 실제 제어·앵글 컨트롤러·CAN 생성기를 사용하지만,
**영상 모델과 EPS/차량은 가정**이다. 10/20/30m/s, 좌우 곡선±0.8m/s²,
양쪽 편차, 초기 중심 오차20/62cm, 전달 지연80/240ms, EPS160ms·60°/s를 비교했다.
기존 중앙 보정과 새 접근 보정 모두 가정48조건 중22조건에서 차체 경계가
선을 넘었다. 특히 이미 차선에 가까운 상태·늦은 응답은 이 보정으로 막지 못했다.
실차 이탈 방지 검증이나 모델 인식 개선을 뜻하지 않는다.

차선 오인식·캘리브레이션/FOV 오차는 잘못된 방향의 보정을 만들 수 있다.
본 기능은 장애물을 판별하지 않아 모델의 깜빡이 없는 회피 경로와 충돌할 수 있다.
급커브에서 일정 곡률로 표현할 수 없는 경계는 개입을 거부한다. 경계에 이미
접근한 뒤의 제한된 조향은 물리적으로 늦을 수 있다. 실차 검증 전 기본OFF를 유지한다.

코드 배포 시 콤마 전체 재부팅이 필요하다. 이전 modeld가 계속 실행되면
과거 중앙 보정을 남길 수 있다. Jetson neural 모델/엔진의 입력 계약은 바뀌지 않는다.
Jetson의 새 문구는 갱신한 HUD 소스가 들어간 패키지를 설치한 뒤 표시된다.
이 문서는 패키지 게시·차량 설치·물리 시험 완료를 주장하지 않는다.

## 후속 요청: 저속 문턱 제거와 Jetson HUD 패키지

사용자가 추가18km/h 제한 삭제와 새 문구 패키지 게시를 명시했다.
보정 자체의 최소속도 비교를 삭제하되 정차/정확한0속도·D단·원래 횡제어 허용과
운전자/깜빡이 양보·조향/CAN 한계는 유지한다. 제어 허용을 새로 만들지 않는다.
속도 제곱의 직접 나눗셈 대신 `max(v,1)^2`로 보정 명령의 변화율을 정규화한다.
이는 계산용 분모 하한이며1m/s 미만을 끄는 문턱이 아니다. 실제 추가 횡가속도와
게이지는 보정 곡률×실제 속도 제곱으로 보고한다.1m/s 이상 명령 수학은 기존과 같다.

Jetson 다섯 모델의 ONNX·엔진 계약을 바꾸지 않고 새 HUD 문구와 상태가 포함된
소스 패키지만 각각 재생성한다. 설치 폴더/준비 판정을 혼동하지 않도록 모델마다
다른 source commit을 사용한다. 실제 게시·공개 재다운로드 검증·최종 핀은 후속
릴리스 기록과 로컬 검증 보고서에서 확인한다. 앞 절의 미게시 상태는 최초 푸시 시점 이력이다.
