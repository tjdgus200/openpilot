# carrot-nav-pv5

기준은 공식 `carrot-nav`의 `682ceeb4`(2026-10-21)이며, 선택한 PV5/HUD 기능만
`codex/jetson-nav-runtime-port`의 `ef79ea37`에서 옮긴 별도 브랜치다.
공식 N16 모델 SHA-256 `01effc679eb46d6036ce0302673a87fe2dcfcc95a679daeeb929679e53c3647a`,
카메라 짝맞춤, locationd 유효성, 제어와 이탈 조건은 유지한다.
공식의 USB HUD 협상, NAV 지도 미리보기, BSD 독립 설정, USB 완료 작업 우선순위
적용 대상 제한도 유지한다. 이후 사용자 요청으로 차선·BSD의
[Jetson CPU/Wi-Fi 실행](jetson_aux_vision_cpu.md)을 추가했다.
이후 추가 요청으로 전용 직접 Wi-Fi만 허용하도록 분리했다. 휴대폰은 인터넷
업링크로만 쓰며 자세한 경로·재연결 제한은 위 문서를 따른다. USB 전원 정책은 이식하지 않는다.

후속 요청으로 직접 AP는 핫스팟 없는 온로드 부팅에서도 자동 생성/복구한다.
별도 낮은 우선순위 작업에서 실행하며 AP/DHCP를 주행 루프에서 기다리지 않는다.
이 시작 조건 변경은 콤마 업데이트/재부팅만 필요하며 기존 대응 Jetson 패키지를 유지한다.
실제 무선 드라이버·공유 PHY의 지연이나 주행 영향이 없다고 검증된 결과는 아니다.

## HUD

- 화면 8에 잔량, 최고/최저 온도, 순간 소비·회생 전력, 냉각수 입구 온도,
  명시적 열관리 상태/전력, 최근 5분 온도 변화, 셀 전압차를 표시한다.
  새 설정/초기화는 8, 저장된 화면 번호는 유지하며 0의 자동 화면도 유지한다.
- **검증된 PV5 CAN 프로필은 포함하지 않는다.**
  `/data/jetlink/pv5-battery-profile.json`이 유효하지 않으면 CAN 수신기를 열지 않고
  `--`와 프로필 필요 문구를 표시한다. CAN 버스·ECU·DID·오프셋을 추측해 활성화하지
  않는다. 진단 송신이나 열관리 제어 명령도 추가하지 않는다.
- 기존 별도 HUD 작업에서 일반 배터리 값은 최대 1Hz, 순간 전력은 최대 10Hz로
  처리한다. CAN 이벤트/재조립/프로필/이력 크기와 필드별 유효시간은 제한된다.
- 하단에 콤마/Orin CPU·메모리와 Orin GPU, 배터리 최고온도 위에 최근 10초
  추론 AVG/P99/MAX를 표시한다. 통계는 별도 낮은 우선순위 작업에서 1Hz,
  Orin VDD_IN 전력만 기존 상태 작업에서 2Hz로 읽는다. GPU 사용률 자체는 고장
  판정에 쓰지 않는다. 지표가 없거나 오래되면 `--`다.
- 전력/온도는 Wi-Fi 아이콘 옆에 표시하며, 그 줄이 없는 화면에서는 화면 안의
  오른쪽 배지를 사용한다. 자동 밝기는 최저 10%, 수신 공백에는 마지막 밝기를
  유지한다. 오프로드 표시가 차량의 온로드/제어 상태를 바꾸지는 않는다.
  차량 데이터가 없으면 속도/기어/크루즈 기본값을 실제 측정처럼 표시하지 않는다.
- 필요하지 않은 3D 화면에서는 JPEG 카메라 미리보기를 만들지 않는다.
  선택한 카메라 미리보기와 Jetson 출력의 기존 10Hz 제한은 유지한다.

## 방향별 BSD 표시

`carState`의 기존 차량 BSD와 신선한 시각 BSD의 OR 결과를 표시에만 사용한다.
시각 BSD는 공식의 `ShareData`/`OnnxBsdEnabled` 조건을 유지하며 Jetson CPU에서
계산하고 Wi-Fi로 결과를 돌려준다. 콤마는 기존 전처리와 결과 병합을 수행한다.
새 검출기, 추가 카메라 전송, 차선변경 제어 조건은 만들지 않는다.

같은 방향의 깜빡이와 BSD가 모두 참이고 `carState` 수신/전송 당시 나이를 합쳐
300ms 이내인 경우에만 경고한다. 시각 BSD 자체의 영상 나이 검사는 공식의
기존 정책을 따른다. 실제 화면 끝 14px 경고선은 처음에는 밝게 표시하고 2Hz,
60% 밝은 구간으로 밝기를 바꾸며 어두운 구간에도 96/255 밝기를 유지한다.
해당 방향 바깥 1/3의 빨간 그라데이션은 최대 알파 36/255로 고정한다.
패널 교환과 무관하게 실제 왼쪽/오른쪽을 지키며, 가운데 1/3은 물들이지 않는다.
차량 경고는 마지막에 그려 우선한다. 수신이 끊기면 이 표시를 유지하지 않으며,
표시가 없다는 것은 옆 차선이 비었다는 뜻이 아니다.

넓은 배경을 깜빡이는 대신 좁은 선에만 주기적 밝기 변화를 적용한 것은 이
보조 화면의 가독성을 위한 설계 선택이다. NHTSA의
[Human Factors Design Guidance for Driver-Vehicle Interfaces](https://www.nhtsa.gov/sites/nhtsa.gov/files/documents/812360_humanfactorsdesignguidance.pdf)는
점멸의 주의 환기 효과와 빈도·듀티·긴급도에 따른 조정을 설명한다.
이 문서가 본 HUD의 2Hz 설정이나 실차 안전성을 검증한 것은 아니다.
기존 렌더 프레임마다 방향당 그라데이션 사각형 1개와 선 사각형 2개만 그린다.
새 타이머·스레드·이미지 버퍼나 프레임률 증가는 없다.

## USB 업데이트

오프로드 또는 **최신 유효 CAN 정보의 P단 + 원속도 `vEgoRaw == 0`**에서 허용한다.
온로드 화면/크루즈 상태 표시만을 이유로 P단 업데이트를 막지 않는다.
속도 필터의 정차 후 잔상을 원속도 대신 사용하지 않는다. `carState`는 valid/alive,
수신 나이 250ms 미만, `canValid`, `!canTimeout`을 모두 만족해야 한다.
P단 해제·속도 발생·수신 공백·USB 끊김은 다음 전송/활성화 요청을 중단한다.
이미 시작된 원자적 설치 작업의 즉시 취소를 보장한다는 뜻은 아니다.

기어/속도 확인이 잠시 끊겼을 때는 USB를 재설정하지 않고 같은 부팅 연결에서
유효한 주차 조건을 기다린다. 다시 승인되면 SHA로 확인한 캐시를 재사용하고
파일 전송은 처음부터 재시도한다. 대기 중에는 파일 바이트나 활성화를 보내지
않는다. 실제 USB I/O 오류·분리는 기존 연결 정리를 수행한다.
큰 모델 준비가 런타임 파일 전송 뒤의 약 7.4%에 끼지 않도록 두 파일을 먼저
다운로드/검사한다. 콤마 배지는 파일 검사·다운로드·USB 전송·P단 대기를 구분하며
준비 블록마다 최대 2Hz로 상태를 갱신한다. 30초 네트워크 대기를 표시할 수 있도록
준비 단계만 최대 35초의 표시 유예를 둔다. 주행/전송 상태와 제어 유효성의 기존
마감은 완화하지 않는다. `host_update.reason`은 기어·속도·CAN/수신 상태를 구분한다.
충전기에서는 성공하고 차량에서는 멈췄다는 관측만으로 이 문제가 유일한 원인이나
차량 전원이 정상이라고 단정할 수는 없다. 본 수정은 PC 재현이며 실차 재확인은 별도다.

Park 예외는 모델을 실행하지 않는 부팅 수신기에만 허용한다. 이미 실행 중인
Jetson 엔진을 주행 중 교체하는 기능은 아니다. SHA-256·크기, ABI/모델 검사,
네이티브 실행 검사, 보호 저장소, 실패 시 이전 릴리스 유지 조건은 유지한다.
정상 모드 Jetson 재부팅과 기존 SHA-256 USB 수신기 등록이 필요하다.
공식 서명 NAS 경로와 공식 키는 수정하지 않는다.

## 추론 포트와 근거의 범위

- GPU 상태 피드백과 전체 상태 유한값 검사는 `CARROT_TRT_DEVICE_STATE`로
  선택한다. 모델 출력/상태 검사, 초기화, 재접속, 실패 시 링크 폐쇄를 유지한다.
- 사용자 후속 요청으로 **비동기 USB 쓰기 추가분은 제거**했다. C3·C3X·C4 모두
  데몬이 공식 `FfsTransport`를 직접 사용한다. `ffs_aio.py`와 네이티브 송신기,
  `CARROT_JETLINK_AIO_WRITE` 배포 옵션을 제거해 이전 환경값 1도 재활성화하지 못한다.
  직렬 송신 본체 `ffs.py`는 최신 공식 `carrot-nav`의 `3a03a39f`와 동일하다.
  공식 watchdog·마감·불확실한 정리 시 재사용 차단·기존 수신 작업과 CPU 배치,
  USB 완료 작업 FIFO2의 커널·워커·소유권·원복 검증은 유지한다. 실험용 core7 배치는 추가하지 않는다.
  후속 요청으로 자동 적용 대상을 C3/C3X/C4의 `tici`/`tizi`/`mici`, aarch64/
  Linux4.9.103으로 넓혔다. 다른 커널·장치나 추적 기능 부재에는 기존 정책을 유지한다.
  C3에서 지연·커널 안정성을 실측한 결과는 아니다. [검증과 범위](jetlink_usb_completion_priority_20261021.md)를 참고한다.
  공식의 별도 선택적 AIO 수신 진단은 송신 최적화와 다르므로 그대로 둔다.
- 이전 C3/Orin RL Nav 한 차례 전후 시험은 조합 상태에서 전체 처리 평균
  43.46→41.90ms, P99 51.99→49.25ms를 관측했지만 최대값은
  60.20→63.26ms였다. 비동기 쓰기 단독 이득이나 N16의 같은 효과를 입증한
  결과가 아니다. 출처: `codex/jetson-nav-runtime-port`의
  [기존 측정 기록](https://github.com/tjdgus200/openpilot/blob/ef79ea37/docs/jetson_runtime_port_20261015.md).
- 미입증 입력 fastpath, TensorRT L5, 프레임 재사용·유효성 완화는 포함하지 않는다.
  현재 N16과 공식 빌드 수준/Timing Cache 정책은 유지한다.

PC 회귀는 유한값/상태 순서·초기화, 전송 프레이밍·마감·정리, 주차 조건,
화면/밝기/통계/BSD/지도 미리보기를 검사한다. CUDA 동작은 대체 구현을 통한
순서 검사와 선택적인 실제 CUDA 시험을 구분한다. 합성 화면은 실제 렌더러로
확인한다. 이 새 조합의 장치 설치·실차 인식·장시간 주행·매 프레임 50ms 완료는
별도 검증이며 여기서 보장하지 않는다.

이번 송신 되돌림은 **콤마 Git Pull과 정상 재부팅**으로 적용되며 아래의 Jetson
패키지는 바꾸지 않는다. Jetson의 주행 추론 USB 호스트는 이 콤마용 FunctionFS
송신기를 사용하지 않는다. GPU 상태 유지와 직접 Wi-Fi, 차선/BSD CPU 계산은 유지한다.
PC에서는 실제 데몬 클래스가 공식 직렬 송신을 선택하는지, 이전 AIO 환경값을
넣어도 475KB 메시지가 한 번의 `writev`로 원래 v2/v3 바이트·패딩을 보내는지,
수신·마감·정리·재접속·완료 작업 우선순위를 검사한다. 실제 장치 지연 측정은 아니다.

사용자가 제공한 비교 화면에는 다음 값이 있다. 새로 측정한 결과가 아니며,
시험 길이가 다르고 core7 배치도 함께 바뀌므로 비동기 단독의 인과 효과로 해석하지 않는다.

| 제공된 시험 | 길이 | 모델 호출 평균 | 최대 | 50ms 초과 |
| --- | --- | --- | --- | --- |
| USB 완료 작업 우선순위 상향 | 120초 | 44.50ms | 49.81ms | 0/2,400회 |
| 위 설정 + core7 + 비동기 | 180초 | 41.00ms | 79.96ms | 10회 |
| 위 설정 + core7 + 기존 수신 | 180초 | 42.66ms | 60.44ms | 3회 |

평균 개선만으로 50ms 마감 준수를 판단할 수 없다. 이 자료와 사용자 요청에 따라
추가 송신 경로를 철회하며, 공식 방식이 모든 장치에서 50ms를 보장한다고 주장하지 않는다.

## 배포와 확인 결과

- [대응 Jetson 패키지](https://github.com/tjdgus200/openpilot/releases/tag/jetson-pv5-aux-wifi-20261021-61878ca0)는
  소스 `61878ca09a3d34356814806cae694e67aa499f50`에서 만들었다.
  묶음은 81,669,609바이트, SHA-256은
  `882ba41388b75231e175c6d18737bd83b6e34f10d32f80780a8cb24bb59157f3`다.
  기존 공개 차선/BSD ONNX 두 개를 포함하며, 주행 모델 가중치·개인키·차량 로그는
  포함하지 않는다. 공개 HTTPS 재다운로드로 크기와 해시를 확인했다.
  브랜치는 콤마 P단 대기/파일 준비를 유지하며, 새 패키지는 차선·BSD의 오류 분류를 지원한다. 새 호스트는
  인증된 오류 응답과 상세 진단 기능을 지원하며, 구형 CPU 호스트의 오류는
  세부 원인을 알 수 없다는 표시를 유지한다. [진단·듀얼 Wi-Fi의 범위](jetson_aux_vision_cpu.md)를 참고한다.
- 이 브랜치의 `usb_host_sha256_release.json`이 해당 패키지를 선택한다.
  공식 서명 `host_release.json`과 N16 모델은 그대로다. 기존 SHA 수신기가 등록된
  Jetson을 콤마에 USB로 연결한 채 정상 모드로 재부팅하면, 콤마가 오프로드 또는
  신선한 P단·속도 0 조건에서 다운로드·전송·활성화를 요청한다.
  캐시가 없으면 **콤마의 인터넷 연결**이 필요하고, Jetson Wi-Fi 연결은 필요하지 않다.
  수신기가 없는 Jetson은 최초 1회 로컬 등록이 필요하며 Git Pull만으로 등록되지 않는다.
- 공식 브랜치로 돌아가 이 USB 선택 파일이 없어지면 기존 공식 서명 NAS 선택으로 복귀한다.
  이미 실행 중인 Jetson 엔진은 유지되므로 공식 런타임 적용에도 정상 모드 재부팅이 필요하다.
- [차선/BSD 진단 소스 자동 검사](https://github.com/tjdgus200/openpilot/actions/runs/39565949638):
  Linux 루트 권한 수신기/복구 103개, 넓은 통합 검사 1,212개(선택적 61개 건너뜀),
  내비/장면 119개, 실제 격리 파일시스템 11개, 격리 Wi-Fi 패킷 11개 통과.

  화면을 확인했다. 최종 아카이브를 격리 Linux 폴더에 풀어 HUD 진입점과 실제
  두 CPU ONNX의 설치 검사를 실행 확인했다. 콤마 주차 대기/전송 보완은 별도 PC

## 기존 PV5 CAN 캡처 확인과 수동 수집 보완 (2026-10-22)

사용자가 저장한 기존 버전 1 JSON을 장치에서 PC로 내려받아 SHA-256을 대조했다.
60.009초, 유효 이벤트 6,001개였으며 송신 에코를 포함한 전체 프레임은 411,694개다.
송신 에코를 제외한 실제 수신 집계는 다음과 같다.

| Panda 수신 버스 번호 | 프레임 수 |
| --- | ---: |
| 0 | 143,978 |
| 1 | 62,038 |
| 2 | 30,817 |

합계 236,833개지만 수집기가 선택한 후보 주소 `0x7E4/0x7EC`는 0개였다.
사용자는 이때 Car Scanner를 연결하지 않았다고 확인했다. **기존 수집기는 두 후보
주소 외의 페이로드를 저장하지 않았으므로, 이 파일로 다른 ID의 배터리 방송 신호를
분석할 수는 없다.** 후보 주소가 없는 사실만으로 버스 선택 오류, BMS 부재 또는
게이트웨이 차단을 확정하지 않는다. 이 주소들이 PV5에서 검증됐다는 뜻도 아니다.

장치에는 `/data/jetlink/pv5-battery-profile.json`도 없었다. 현재 HUD는 검증된
수신 프로필이 있어야 해석하며 ECU에 조회나 ISO-TP 흐름제어를 보내지 않는다.
따라서 이번 자료로 온도·SOC·열관리 전력을 추측해 프로필을 활성화하지 않았다.
OBD 앱에서 보이는 응답이 콤마의 하네스에도 보이는지는 별도 확인이 필요하다.

같은 수동 명령으로 실행하는 `capture_bms_visible_can.py`의 버전 2 출력에는
버스·ID별 수신 횟수와 길이 목록을 추가했다. 최대 1,024개 키, 키당 최대 3개
원문 표본을 20초 이상 간격으로 보관한다. 상한을 넘긴 프레임 수를 명시하고,
기존 후보 응답 표본 상한 2,048개와 버스 상한 32개도 유지한다. 다른 ID가 많아도
기존 후보 집계는 계속한다. 잘못된 이벤트와 송신 에코는 증거에서 제외한다.

이 도구는 **사용자가 수동 실행할 때만** 기존 `can` 스트림을 읽는다. 새 CAN 송신,
자동 수집, 제어·주행 추론 루프 변경은 없다. 별도 SCHED_OTHER/nice19 프로세스이며
1~120초 제한, 새 파일만 생성, 파일 권한 0600을 사용한다. 원문에는 다른 차량 신호가
들어갈 수 있으므로 로컬 증거로만 취급하고 공개 저장소·터미널 출력에 넣지 않는다.

PC 검사는 비후보 ID·버스별 구분, 송신 에코/무효 이벤트 제외, 표본 시간 분산,
상한 이후 후보 응답 유지, 잘못된 길이와 메모리/출력 상한 등 6개를 통과했고
Ruff도 통과했다. PC 합성 408,068프레임 처리의 3회 중앙값은 기존 0.054초,
추가 목록 수집 0.126초, 후자의 파일은 약 188KB였다. **이는 PC 수치이며 콤마
CPU 실측이나 주행 안전 검증이 아니다.** 확대 HUD 회귀는 로컬의 불완전한
Cap'n Proto 스키마 환경에서 중단됐으므로 그 실행을 통과로 기록하지 않는다.
새 도구의 실차 재수집·신호 식별과 Car Scanner 값 대조는 아직 수행하지 않았다.
