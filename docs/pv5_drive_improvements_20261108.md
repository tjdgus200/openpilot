# PV5 추종·지연·야간 입력 진단과 단계별 주행 안내

## 적용 범위

요청한 다섯 항목을 구현했다. 추종·중앙 보정·지연은 기존 로그를 PC에서 분석하고,
정차 FOV 화면에는 C3/C3X의 자동노출 측정 영역을 함께 표시한다. 콤마와 Jetson HUD의
끼어들기 안내는 관측·추적·감속 반영을 구분한다.

모델 가중치, 입력 전처리, FOV 선택, PID/차량 파라미터, 중앙 보정 진입 조건과
0.08m/s² 상한, CAN/EPS 한계는 변경하지 않는다. 진단을 이유로 성능 진단을
상시 켜거나 모델을 추가 실행하지 않는다. 진단 도구는 차량 부팅·modeld·controlsd에서
호출하지 않으며 PC 전용 가드가 있다. 실측 근거 없이 제어·노출 게인을 바꾸지 않는다.

## 1. 목표 경로와 조향 추종 분리

`tools/jetlink/pv5_drive_report.py`는 전체 cereal 스키마로 로컬 rlog를 읽는다.
zstd/bz2/비압축 입력을 스트리밍하며 메시지당 최대 32MiB, 카메라별 64프레임,
지표별 최근 4096개 값과 최대 1200개의 10Hz 추종 표본으로 메모리를 제한한다.
원시 이벤트·영상·위치·운전자 데이터는 보고서에 내보내지 않는다.

- 신선하고 유효한 PV5 D단·횡제어 활성 상태에서 수동 개입/조향 오류를 제외한다.
- 요청각−적용각과 적용각−측정각을 분리한다. 동기화된 명령 응답 ID가 없으므로
  이 차이를 물리적 응답 지연이나 EPS 고장으로 단정하지 않는다.
- 양쪽 차선 확률이 85% 이상이고 폭이 2.8~4m이면 같은 모델 프레임의 차선 중앙과
  모델 경로 간 횡방향 차이를 1.5초 전방 거리에서 계산한다. 실제 차량의 정답 횡오차가 아니다.
- 전체 평균/RMS/최대와 **최근 4096개 표본의 P99**를 구분한다. 모델 확률을
  검증된 인식 정확도나 안전 확률로 취급하지 않는다.

```sh
# 준비된 PC Python 환경에서, 순서대로 나열한 같은 주행의 로그만 사용
python tools/jetlink/pv5_drive_report.py /path/to/rlog.zst --label light-speed-2-night --output /tmp/pv5-report
```

`report.json`과 `report.md`에 분석 결과를 저장한다. 입력 파일 해시를 기록하되
파일 경로나 원시 로그를 공개 결과에 복사하지 않는다. qlog는 원래 메시지 누락이
있으므로 service_counts/coverage를 먼저 확인한다.

## 2. 중앙 보정의 상태별 관측 시간

기존 `controlsState.pv5LaneCenterStatus/WaitReason`을 읽어 보정·앞차·BSD·차선 품질·
레인모드·운전자·입력 대기 시간을 합산한다. 상태 사이 최대 0.2초만 누적하며
로그 공백은 별도 집계한다. 마지막 상태를 파일 끝까지 연장하지 않는다.
보정 비율의 분모는 로그에서 확인한 controlsState 시간이며 전체 실제 주행 시간이 아니다.
기능을 켜거나 차단 조건을 완화해서 개입률을 높이지 않는다.

## 3. 영상→제어 메시지 지연과 선택적 자원 기록

- 모델의 EOF→모델 발행, 모델 발행→controlsState 발행, EOF→controlsState 발행을 분리한다.
- SOF 지표는 카메라와 모델의 정확한 프레임 ID가 대응할 때만 계산한다.
  최신 카메라 프레임을 임의로 연결하지 않는다. USB/다른 호스트 시계를 빼지 않는다.
- EOF→제어 메시지 발행은 CAN 전송과 물리적 조향 응답을 포함하지 않는다.
- 이미 수집된 runtimeTiming이 있을 때만 USB/GPU/큐/IPC 등 단계별 가중 평균과
  기록된 최대값을 보여준다. 1초 평균으로 프레임 P99를 만들거나 다른 프레임의
  최대값들을 빼서 시간을 추정하지 않는다. 미수집 항목은 미수집으로 남긴다.
  커널 schedstats가 꺼진 경우 runqueue 대기시간을 0ms로 해석하지 않고 미수집으로 처리한다.
- 기존 tegrastats 파일은 `--tegrastats /path/to/stats.txt`로 별도 집계할 수 있다.
  EMC는 현재 주파수에 대한 사용률이며, 이 숫자만으로 대역폭 병목을 판정하지 않는다.
  이 옵션은 장치에 접속하거나 tegrastats를 시작·종료하지 않는다.

현재 모델 우선 HUD admission, Q92/FPS, 공유 USB의 오류 처리와 freshness는 유지한다.
진단 도구 자체는 주행 프로세스에서 실행되지 않는다. 표시 변경의 실제 CPU 비용이나
실제 지연 절약량은 Orin/C3X 측정 전에는 수치로 주장하지 않는다.

## 4. 저조도 입력 확인

기존 정차 FOV 미리보기에 보라색 `AE METER AREA`와 published grey/target/gain을 추가했다.
확인된 C3/C3X 1928×1208 AR/OX 구성에서 camerad의 정수 계산을 재현하며,
알 수 없는 센서/해상도는 영역을 추측해서 그리지 않는다. 광각·일반각 2초 교대와
미리보기 pitch 후보는 유지한다. 노출 값은 2Hz 이하로 읽고 렌즈가 바뀌면 갱신한다.
새 픽셀 readback, 필터, 노출 제어 또는 모델 전처리는 없다.

여러 모델의 저장 보고서는 아래처럼 나란히 비교한다.

```sh
python tools/jetlink/pv5_drive_report.py --compare /path/n16/report.json /path/flip-flop/report.json /path/ctv3m/report.json /path/light-speed/report.json /path/light-speed-2/report.json --output /tmp/pv5-comparison
```

모델/장면 label은 수동 메모이며 실행 모델의 식별 증거가 아니다.
동일 영상 재생과 정답 라벨을 확인하지 않은 보고서는 모델 인식 성능 순위를 만들지 않는다.
**이번에는 새 야간 실영상의 다섯 모델 추론 비교를 수행하지 않았다.** 같은 카메라 영상,
각 모델에 맞는 보조 입력/반복 상태, 정답 라벨을 갖춘 별도 PC 재생이 필요하다.
합성 입력 계약 검사가 실제 저조도 인식 개선의 증거를 대신하지 않는다.

## 5. 같은 차량의 관측·추적·감속 반영 안내

콤마 3/3X와 각 Jetson 패키지는 같은 helper를 사용한다.

1. 기존 유효한 cut-in 위험만 확인: `옆차 끼어들기 경계 중`.
2. 위험 차량과 계획에서 선택한 선행차의 유효한 radarTrackId가 같고 종제어가 활성:
   `끼어들기 차량 / 선행차로 추적 중`.
3. 위 조건에 더해 계획 aTarget과 실제 aEgo가 모두 −0.1m/s² 미만이고 가속페달 해제:
   `끼어들기 차량 / 감속 반영 중`.

추적·감속 단계는 150ms 동안 조건이 유지된 뒤 승격한다. 초기 위험 표시는 지연하지 않는다.
ID 미확인·다른 차량·낡은 계획/레이더·가속페달·CAN timeout에는 상위 단계를 표시하지 않는다.
현재 위험이 없어졌을 때 다른 선행차를 과거 끼어들기 차량으로 이어 붙이지 않는다.
감속이 해당 차량 때문에 발생했다는 인과관계까지 검증한 것은 아니며, 명령과 측정이
동시에 해당하는 상태라는 뜻이다. 제동/CAN/레이더 선정 동작은 변경하지 않는다.

큰 차량 경고·조향 경고 우선, 상황 유지, 정착 후 최소 1초, 220ms 퇴장은 보존한다.
새 두 문구는 두 줄로 배치해 기존 C3X/HUD 크기에 맞춘다. 추가 경고음은 없다.

## 검증 및 남은 단계

필수 모델 보존 목록에 오프라인 보고서·노출 영역 검사를 추가했다. 실제 배포할 다섯
격리 패키지에서 단계별 문구와 기존 경고 우선순위를 네이티브 렌더링한다.
모델 입력/출력과 제어 루프 회귀, 지연/만료/수동 개입·다른 ID·오염된 로그 검사도 유지한다.
실차 화면·EPS·RF·Orin 지연·야간 정답 인식 검증은 별도이며 PC 결과로 통과 처리하지 않는다.

최초 PC 필수 검사 **1,254 passed / 0 failed / 0 skipped**, C3X 2160×1080 단계별 팝업과
양쪽 렌즈 노출 영역의 네이티브 렌더링, 다섯 격리 Jetson 아카이브의 두 줄 안내·기존
경고 우선순위·모델 큐·입력 만료 검사를 통과했다. 새 코드의 Ruff 검사와 사용자 문서
매핑 검사도 수행했다. 기존 UI 검사 파일의 unittest import lint는 기존 항목이다.

| 모델 | 패키지 소스 |
|---|---|
| N16 | d7ebf7a0 |
| Flip Flop | 3a090b86 |
| CTV3M | a97e7257 |
| Light speed | ae966c9f |
| Light speed v2 | c606ca01 |

각 모델의 공개 릴리스 파일 네 개씩, 총 20개를 다시 다운로드해 SHA-256과 크기를
확인한 뒤 위 패키지들을 자동 업데이트 대상으로 지정했다. 기존 모델·엔진 핀은 보존했다.
커널 통계가 꺼진 경우의 결측 처리 회귀도 추가했으며 오프라인 보고서 검사 7건을 통과했다.

모델 ONNX·모델별 최적화 자격과 입력 계약은 변경하지 않았다. 추종·보정·지연 보고서의
숫자를 실주행 개선량으로 보고하지 않으며, 실제 야간 비교와 차량 성능 수치는 미수집이다.
