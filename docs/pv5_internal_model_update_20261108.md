# 내부 모델 소유 중 Jetson 업데이트

차량 속도를 업데이트 허가로 쓰지 않는 별도 경로를 추가했다. 대상은 USB
연결이 끊겨 보이는 장치가 아니라 실제 외부 추론에 사용되지 않는 Jetson이다.

## 동작

1. 변경된 같은 모델의 패키지가 있을 때 transport daemon이 배타 유지 요청을 쓴다.
2. modeld는 외부 client가 없을 때만 요청을 받아 대기 중 join/warp 준비를 취소한다.
   기존 내부 모델에 같은 입력을 전달하고 정상 반환한 뒤 소유권 확인을 보낸다.
3. 250ms 이내의 토큰 일치 확인이 있을 때 속도·기어와 무관하게 허용한다.
   확인은 약 100ms 주기, 요청 읽기는 200ms 주기이며 작은 /dev/shm 파일만 쓴다.
   요청자가 멈추거나 modeld가 재시작해도 hold는 명시적으로 해제될 때까지 남는다.
4. 실행 중인 Jetson은 별도 capability를 협상한다. 최근 1초간 외부 추론 요청이
   없을 때만 해당 handoff를 받으며 ACK 이후 추가 추론을 받지 않는다.
   root worker는 private 요청을 재검사하고 서비스 종료를 확인한 뒤 빈 gate를 연다.
5. 기존 SHA-256·모델·크기·저장소 검사, 순차 USB 전송, 합성 엔진 probe와 rollback을
   그대로 사용한다. 허가가 끊기면 활성화를 보류하고 같은 연결에서 재확인한다.
6. 콤마 프로세스 시작 때의 패키지 source와 새 패키지가 다르면 설치는 완료하되
   Jetson 서비스를 시작하지 않는다. DATA의 대기 기록은 worker/Jetson 재시작에도 남는다.
   같은 콤마 boot ID의 daemon/modeld 재시작만으로 해제되지 않는다. 실제 콤마 재부팅과
   일치하는 source를 확인해야 준비·연결을 재개한다. 콤마 자동 재부팅은 추가하지 않는다.
7. 정상 엔진 준비 후 hold를 해제한다. 추론 join은 원래 정차 또는 운전자 조향 개입
   조건을 유지한다. 속도 무관 허용은 업데이트 조건이며 주행 중 임의 모델 전환이 아니다.

이 업데이트는 런타임 서비스 재시작을 사용하며 OS/커널을 flash하거나 불필요한
전체 Jetson OS 재부팅을 추가하지 않는다. 설치된 bootstrap도 다음 부팅용으로
갱신하되 현재 부팅의 활성화 정책은 보존한다. 구형 수신기는 최초 한 번 P/오프로드 상태에서 Jetson을 재부팅하여
새 capability를 설치해야 할 수 있다.

## 함께 발견한 문제

기존 running-runtime handoff는 실제 ModelSpec의 `nbytes`를 manifest의 `size`와
비교해야 하는데 `spec['size']`를 읽었다. 실제 카탈로그 스펙에서는 KeyError로
handoff가 거절될 수 있었다. 실제 N16 카탈로그로 비교하는 회귀검사를 추가했다.

## 검증 범위

PC에서 실제 ownership, JoiningModel의 내부 입력·출력 전달, lease 만료/누락,
최근 외부 추론 중 거절, 설치 후 콤마 reboot 대기와 재시작 복구를 검사한다.
모델 가중치·텐서·FOV·조향/종방향 제어 값은 변경하지 않는다.

PC 합성 검사는 실제 USB hotplug, Orin TensorRT 빌드 시간, 주행 중 콤마 CPU·I/O
경합 또는 장치 재부팅 내구성을 증명하지 않는다. 공유 자원이 있으므로 추론 지연이
물리적으로 0이라고 보장하지 않는다. 기존 bulk CPU affinity/일반 스케줄링을 유지한다.

## 2026-11-08 배포 기록

최종 PC 회귀 1,243건, 실패·스킵 0건. 다섯 모델의 실제 아카이브를 격리 추출해
server import와 네이티브 HUD 표시를 검사했고 공개 파일 20개를 재다운로드해
해시·크기를 대조했다. 실차·물리 USB·Orin 타이밍 검증은 하지 않았다.
모델별 source는 다음과 같다: n16 `4f61ca12`, flip-flop `af142946`, ctv3m `8fffe52c`, light-speed `aeb8ef1d`, light-speed-2 `eed1abaf`.

HUD 개선도 같은 패키지에 포함한다. 10/15/20/25/30 설정과 세 여유 시간 조합의
60초 PC 재생에서 HUD 갱신 간격 300ms 미만 및 모델 시점 전 4ms 여유를 검사했다.
원격의 2026-11-08 임시 내비게이션·ADB 진단 변경(3ad45b12)도 보존해 통합했다.
