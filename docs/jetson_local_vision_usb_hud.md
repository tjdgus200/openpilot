# 콤마 로컬 ONNX와 USB HUD 복원 — 2026-10-22

`carrot-nav-pv5`는 사용자 요청에 따라 Wi-Fi 보조 영상/결과 경로를 중단한다.
차선·시각 BSD 서비스, 웹 화면, 결과 병합과 설정 범위는 공식 `carrot-nav`
`ec36d5e5`를 따른다. 주행 모델 N16, GPU 상태 유지, 공식 직렬 USB 전송,
USB 완료 우선순위, P단·정지 업데이트 조건은 변경하지 않는다.

## 실행 및 데이터 경로

1. 기존 온로드 준비 조건과 `ShareData`에 따라 콤마에서 차선 ONNX를 실행한다.
   시각 BSD는 별도 `OnnxBsdEnabled`와 기존 ROI/차로 폭 조건을 따른다.
2. `card.py`가 방향별로 **차량 BSD OR 유효한 시각 BSD**를 병합한다.
   ONNX 미감지·꺼짐·실패·오래된 결과는 차량 BSD를 지우지 않는다.
3. 병합된 `carState.leftBlindspot/rightBlindspot`는 기존 HUD 스냅샷에 포함된다.
   별도 BSD 패킷/타이머/소켓을 추가하지 않는다. 스냅샷 생성은 기존 최대 10Hz이고,
   USB 전송은 공식 HUD 전송 구간과 기존 중복·만료 검사를 그대로 따른다.
4. Jetson HUD는 깜빡이와 무관하게 신선한 BSD에 즉시 해당 방향 빨간 선을 표시한다.
   기존 2Hz 밝기 변화, 바깥 1/3 그라데이션, 300ms HUD 신선도 검사는 유지한다.

차선 기본 간격은 400ms, BSD는 250ms이고 최소 설정값은 각각 50ms다.
이는 공식 값의 복원이며 기존 저장된 간격/토글/ROI는 변경하지 않는다.
공식 BSD 후속 검사와 CPU 배치/OpenCV 설정도 복원한다. 콤마 CPU 계산 부하는
원격 추론 때보다 늘 수 있으므로 주행 성능 향상이나 무영향을 주장하지 않는다.

Jetlink 세션에서 보조 Wi-Fi 작업을 더 이상 시작하지 않고 HUD Wi-Fi 폴백도
사용하지 않는다. 기존 네트워크 설정은 SSH/인터넷용으로 유지한다. 호환용 원격
클래스와 Jetson 수신기는 남아 있지만 현 콤마 경로에서는 협상/호출하지 않는다.
`v_asm_inference.py`의 `predict_square` 함수 분리도 구 수신기 호환용으로 유지하며,
로컬 입력과 추론 계산은 공식과 동일하다.

## 적용

2026-10-22의 USB 전송 복원은 콤마 브랜치를 업데이트하고 정상 재시작하면 적용된다. 당시 선택된 Jetson
`b21f1f4c` 패키지는 USB HUD를 지원하므로 패키지/선택 manifest를 바꾸지 않는다.
USB HUD 기능을 광고하지 않는 구형 Wi-Fi 전용 수신기는 자동 우회하지 않는다.
진행 중인 구 Wi-Fi 세션은 정상 재시작으로 종료하고 새 세션에서 시작하지 않는다.

## 검증 범위

PC 검사는 실제 CPU ONNX 모델, 공식 차선/BSD/ROI/토글/NV12 회귀 검사,
방향별 차량·시각 BSD 조합과 만료 결과의 USB 직렬화/경고 표시를 다룬다.
USB HUD 중복/만료/크기 제한과 내비 전송 구간 검사도 유지한다.
이는 새 버전의 실제 콤마 CPU 부하, Jetson 20Hz, 실차 안전성 검증을 대신하지 않는다.

### 2026-10-23: 측면 BSD 경고가 새 데이터를 거부하던 시각 수정

기존 `SnapshotBuilder.packet()`은 `SubMaster.update()` 전에 `sent`를 잡았다.
반면 `carState`의 `received`는 update 안에서 더 늦은 시각으로 기록된다.
따라서 새 데이터인데도 `sent - received < 0`이 되어, 300ms 신선도 검사에서
측면 빨간 바와 그라데이션이 차단될 수 있었다. 기존 장면의 차선 빨간 표시는
이 추가 검사를 거치지 않아 표시되는 반면 측면 효과만 빠지는 증상을 설명한다.
해당 사용자의 실제 설치 상태를 조회해 원인을 확정한 것은 아니며, 이 코드
문제 자체는 실제 builder와 cereal 직렬화를 사용하는 PC 검사에서 재현했다.

완성한 스냅샷에 `sent`를 기록하도록 수정했다. 선택적 카메라/배터리 준비 시간도
수신 데이터의 나이에 반영한다. 음수 나이를 0으로 보정하거나 300ms·valid·alive
검사를 완화하지 않는다. 최대10Hz 생성 주기와 USB 전송 시점, 주행 제어는 유지한다.

좌/우/양쪽/없음 및 새 데이터/오래된 데이터/느린 준비 작업 조합의 회귀 검사12개를
추가했고, BSD·기본 HUD·온도·밝기·배터리·지도·자원 표시 관련 PC 검사237개를 통과했다.
이전에는 새 데이터의 수신 시각이100.003인데 sent가100.000인 순서를 재현했다.
실제 장치에서 화면 복구를 확인한 결과는 아니다.

이번 변경은 콤마 송신 코드에 적용하면 된다. 아래 배포한af987fb0 호스트 패키지의
수신 형식과 호환되므로 새 호스트 패키지나 인증/설치 조건 변경은 없다.
깜빡이 없는 경고를 포함한 host renderer 변경 자체는 기존 안내대로af987fb0 설치가
필요하다. 콤마만 pull한 사실로 Jetson 설치 완료를 추정하면 안 된다.

### 2026-10-23: 깜빡이와 독립적인 BSD 경고

기존 `hud_bsd.warning_sides`는 같은 방향 깜빡이가 켜져 있어야 빨간 경고를
표시했다. 이 표시 전용 조건을 제거했다. 신선하고 유효한 `carState`에 왼쪽
BSD가 있으면 왼쪽, 오른쪽 BSD가 있으면 오른쪽을 표시한다. 양쪽이면 양쪽이다.
ONNX 서비스나 설정을 표시 조건으로 추가하지 않는다. 기존 차량 BSD OR 신선한
ONNX BSD 병합을 그대로 사용하므로 ONNX가 없거나 잘못됐거나 오래돼도 차량
BSD는 유지된다. 차량에서 실제 BSD 신호를 제공하지 않는 상황을 감지 성공으로
간주하거나 경고를 만들어내지는 않는다.

2Hz 빨간 선, 바깥 1/3 그라데이션과 300ms 데이터 만료 정책은 유지한다.
새 CAN 요청, 추론, 전송 주기, 프로세스는 추가하지 않는다. 차선변경 제어의
깜빡이·BSD 조건도 변경하지 않는다. 차량 BSD가 활성화된 동안 표시한다는 뜻이며,
차량 데이터가 없거나 오래됐을 때까지 경고를 계속 유지한다는 뜻은 아니다.

이 변경은 Jetson 렌더러 코드이므로 **새 Jetson 패키지 설치가 필요**하다.
콤마 소스 업데이트만으로 기존 Jetson `b21f1f4c`의 표시 조건은 바뀌지 않는다.
새 패키지도 기존 SHA/크기·모델·실행 검사와 P단·정지 업데이트 조건을 유지한다.

PC 검사 183개가 통과했다. 좌우 깜빡이/BSD의 16가지 조합, ONNX 없음·무효·만료·
유효 결과와 차량 BSD의 조합을 실제 cereal 직렬화→가상 USB→HUD 경고까지 확인했다.
만료 데이터 차단, 2Hz 표시, 좌우 레이아웃 및 기존 차량 경고의 우선순위도 유지된다.
이 결과는 실차 BSD 수신이나 실제 HUD 화면을 확인했다는 뜻은 아니다.
