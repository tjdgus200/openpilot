# 사용자 USB 업데이트의 SHA-256 모드

배포 파일 `host.tar.gz`와 `model.onnx`는 원래부터 암호화되지 않은 공개 파일입니다.
이 모드는 사용자 USB 경로에서 전자서명 대신 콤마 브랜치에 고정한 SHA-256과
파일 길이를 확인합니다. SHA-256은 파일 손상을 검출하며 제작자 신원을 인증하지
않습니다. 패키지와 예상 해시를 함께 바꾸면 같은 검사를 통과할 수 있습니다.
신뢰하는 브랜치의 파일과 실제로 연결한 USB 상대를 사용하세요.

공식 NAS 업데이트의 서명·공개키는 바꾸지 않습니다. 다른 모델의 패키지, 잘못된
OS/TensorRT ABI, 부족한 DATA 공간, 잘못된 파일 소유권, 미완성 전송, 실패한 실행
검사도 계속 거부합니다. USB 업데이트는 기존 오프로드 또는 유효한 P단·정차·보조
해제 조건을 사용하며 실행 중인 모델을 덮어쓰지 않습니다.

## 기존 Jetson의 한 번 필요한 수신기 설치

기존 수신기는 서명 없는 형식을 이해하지 못합니다. 콤마 브랜치만 바꾸면 기존
수신기의 검사를 제거할 수 없습니다. 새 수신기는 root 소유의 로컬 정책 파일이
있을 때만 SHA 모드를 알립니다. USB로 받은 패키지가 이 정책을 켤 수는 없습니다.

차량에서 분리하거나 시동을 끄고 Jetson에 직접 로그인할 수 있을 때, 신뢰하는
이 브랜치의 작업 복사본에서 아래 명령을 실행합니다. `<SOURCE>`를 복사본의
절대 경로로 바꾸세요. 기존 프로그램과 업데이트 서비스가 모두 중지돼 있어야 합니다.
복구 마운트로 설치할 때는 `--runtime`에 마운트한 DATA의 `runtime` 경로를 사용하며
호스트 PC의 systemd를 조작하지 않습니다.

```bash
sudo systemctl stop carrot-jetlink carrot-jetlink-hud carrot-jetlink-boot-gate carrot-jetlink-update-stage
sudo /opt/carrot-jetlink/venv/bin/python <SOURCE>/tools/jetlink/install_usb_receiver.py --runtime /opt/carrot-jetlink --sha256
sudo reboot
```

개인키나 새 공개키 등록은 필요 없습니다. 기존 공식 키와 등록된 사용자 공개키는
보존합니다. 새 수신기와 정책은 DATA에 설치되며 QSPI·운영체제 이미지는 바꾸지 않습니다.

## 콤마에서 선택하는 경로

- Jetson이 `carrot_usb_sha256_v1=true`를 알리면 공개
  `usb_host_sha256_release.json`을 사용합니다. 서명 필드가 없는 형식 2입니다.
- 구형 수신기에는 소스·모델·패키지 해시가 모두 같은 기존 서명 패키지만 사용합니다.
  서로 다른 패키지로 임의 전환하지 않습니다.
- SHA 수신기가 패키지를 거부하면 다른 검증 방식으로 다시 시도해 우회하지 않습니다.
- `host_update.integrity`의 `sha256` 또는 `signature`로 실제 선택 경로를 볼 수 있습니다.
  오류의 `[begin]`, `[transfer]`, `[verify]`는 거부된 USB 단계를 나타냅니다.

파일이 없으면 콤마가 HTTPS로 내려받고 USB로 전송합니다. Jetson Wi-Fi는 필수가
아닙니다. 다운로드·전송 양쪽에서 길이와 해시를 확인하고 임시 파일은 검사에 통과한
경우에만 등록합니다. 이미 내용이 같은 등록 패키지는 재전송하지 않습니다.

공식 콤마 브랜치로 돌아가면 그 브랜치의 공식 서명 업데이트 경로를 그대로 사용합니다.
현재 발생한 포괄적인 패키지 거부 오류는 저장 공간이나 파일 권한 문제일 수도 있으므로,
이 모드가 그 오류를 해결했다고 간주하지 마세요. 장치 설치·실차 검증은 별도입니다.
